# Week 2 – Ethical Hacking & Web Security

This week focused on ethical hacking and web application security in a controlled legal learning environment. The main goal was to study common web vulnerabilities, test them carefully in a safe practice setup, and document the findings in a clear security report.

## Week 2 Objective

The objective of this week was to understand how web applications can be vulnerable to common attacks, how to identify those weaknesses, and how to document the findings in a structured way. The work also introduced the basics of authentication, session handling, input validation, and web security assessment.

## Environment and Tools Used

- OWASP Juice Shop used as a controlled legal educational practice environment
- Browser-based testing and inspection tools
- Developer tools for reviewing requests, responses, and client-side data
- Local storage and session review for authentication-related behavior
- Documentation and evidence capture in Word files and notes

## Tasks Completed

- Task 2.1 – OWASP Top 10 study and summary
- Task 2.2 – Vulnerability identification in OWASP Juice Shop
- Task 2.3 – Authentication and session analysis
- Task 2.4 – Penetration-testing style report

## Main Findings

This work identified key issues that are common in web applications, including:

- SQL injection / authentication bypass in the practice environment
- Cross-site scripting (XSS) findings
- Weaknesses in input validation and authentication handling
- Session-related behavior and local storage review for authentication data

The token-related evidence used in this task was intentionally redacted. No actual credentials, passwords, or JWT values were recorded or shared.

## Documentation and Evidence

The evidence for this week is stored in the task folders and in the copied Word documents for each task. The material includes the activity notes, findings logs, screenshots, and summary reports relevant to the work completed.

## Final Outcome

Week 2 helped build a practical understanding of web security testing in a safe and legal educational setup. The work demonstrated how common application weaknesses can be identified, assessed, and reported without claiming an exhaustive or full-scale penetration test.
